BEAVER Benchmark

What it is, how it works, and how Few-shot on the dw dataset is run

Core idea

BEAVER is a text-to-SQL benchmark built around enterprise-style databases, where the model must map a natural-language question to SQL over complex schemas.

Why it matters

It focuses on harder problems than many public benchmarks: schema complexity, domain knowledge, joins, and multi-step reasoning.

Why BEAVER exists

From public benchmarks to enterprise reality

  • Most older text-to-SQL benchmarks use cleaner, more standard schemas.
  • BEAVER is built from private-enterprise-style warehouse data and realistic analytical questions.
  • The benchmark is designed to test not only whether SQL is correct, but also where reasoning breaks down.
The paper’s main message is that current models still struggle in enterprise settings, even when the SQL is conceptually simple to humans.
Datasets & Methods

The four datasets

dw

Primary data warehouse dataset with analytical queries over enterprise schemas.

dw_real

Real-world variant of dw with additional complexity and edge cases.

neutron

Enterprise dataset with domain-specific schema patterns.

nova

Diverse schema structures and data modeling approaches.

Each dataset includes questions, target SQL, schemas, example rows, and metadata for schema linking.

Methods Explained

Few-shot: Simple baseline

What it does

  • Provides one example question-to-SQL pair
  • Supplies the current question and schema
  • Asks the model to generate SQL
Methods Explained (continued)

DAIL-SQL: Smart examples

What it does

  • Uses example selection instead of random few-shot examples
  • Chooses examples semantically similar to the current question
  • Aims to show the model the most relevant demonstration
  • More sophisticated than Few-shot, often produces better results
Methods Explained (continued)

DIN-SQL: Decomposition + Self-correction

What it does

  1. Schema linking: identifies relevant tables and columns
  2. Query decomposition: breaks complex queries into sub-queries
  3. SQL generation: produces the final SQL
  4. Self-correction: if SQL fails, it attempts to fix the query
Methods Explained (continued)

ReFoRCE: Agentic refinement

What it does

  • Candidate generation: generates multiple SQL candidates
  • Majority voting: selects the most common output
  • Column exploration: iteratively refines column selections
  • Execution feedback: uses actual results to guide refinement

Most complex but often achieves highest accuracy. More computationally expensive.

Evaluation Modes

How BEAVER measures performance

Execution Accuracy

Did the generated SQL produce the same result as the gold SQL?

All-or-nothing metric: either the result matches or it doesn't.

Subtask Evaluation

Fine-grained analysis of five critical steps:

  • Table retrieval
  • Column mapping
  • Join key detection
  • Domain knowledge
  • Query decomposition

Subtask evaluation reveals where models fail, enabling targeted error analysis.

Paper-level context

BEAVER results from the original paper

  • Strong agentic systems using GPT-5.2 achieve about 10.8% execution accuracy.
  • When given oracle-style subtask hints, accuracy rises to about 30.1%.
  • This 20-point gap reveals that the main bottleneck is in the reasoning subtasks, not the final SQL generation.
The benchmark is challenging because the reasoning steps are hard, not just the syntax of the final query.
What is in the prompt

Prompt contents for the Few-shot run

Always included

  • A system instruction telling the model to produce MySQL SQL
  • One few-shot example from the dataset
  • The current user question
  • Formatted table descriptions with example rows and columns

Optionally included

  • Mapping: question phrases to columns
  • Join keys: how tables should be connected
  • Domain knowledge: useful semantic hints
  • Query decomposition: sub-questions or subqueries

This matches the logic in the repository’s Few-shot prompt builder.

The dw dataset

What dw contributes

The dw dataset is one of the benchmark’s main evaluation domains. In the repository, it includes:

  • question-SQL pairs
  • table metadata
  • example prompts and example SQL
  • retrieval data for selecting relevant tables

Example from the repo

The example prompt for dw includes a complex question about rooms, buildings, and departments, plus a multi-table SQL query.

Settings

What the different settings mean

Setting 0

Standard end-to-end run with no extra hints.

Setting 1

Adds hints for gold tables, column mapping, and join keys.

Setting 2

Adds even more guidance: domain knowledge and query decomposition on top of the setting 1 hints.

Practical effect

Higher settings make the prompt easier for the model by supplying more explicit intermediate structure.

Takeaway

Bottom line

  • BEAVER is a realistic, enterprise-style text-to-SQL benchmark.
  • Few-shot is a lightweight baseline that uses an example plus structured context.
  • The dw dataset is one of the benchmark domains used for evaluation.
  • The benchmark is useful because it exposes where models fail beyond simple SQL generation.
